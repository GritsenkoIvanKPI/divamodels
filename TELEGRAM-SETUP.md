# Заявки → Telegram

Заявки с сайта уходят в группу **DIVA MODELS** через бота **@bunxymodels_bot**.

Отправляют заявки два места, оба уже подключены:

| Форма | Файл | Метка в сообщении |
|---|---|---|
| Попап на сайте | `apply-form.html` | `Попап на сайте` |
| Рекламный лендинг | `apply.html` | `Рекламный лендинг` |

---

## Инструкция: подключить безопасно (20 минут, бесплатно)

Сайт лежит статикой на GitHub Pages — сам он ничего отправлять не умеет.
Поэтому заявку принимает маленький бесплатный посредник в Cloudflare, а он
уже пишет в Telegram. Токен хранится у Cloudflare и **в браузер не попадает**.

```
Ваш сайт  →  Cloudflare (токен здесь)  →  группа в Telegram
 файлы          бесплатно, 100k/день        заявки приходят
```

---

### Шаг 0. Сменить токен — обязательно

Старый токен засветился: он был в переписке и какое-то время лежал в файлах
сайта. Считаем его скомпрометированным.

1. Telegram → [@BotFather](https://t.me/BotFather)
2. Отправить `/revoke`
3. Выбрать бота **@bunxymodels_bot**
4. BotFather пришлёт **новый токен** — он и нужен дальше

Старый перестанет работать сразу.

---

### Шаг 1. Создать воркер

1. Зайти на [dash.cloudflare.com](https://dash.cloudflare.com) (регистрация
   бесплатная, карта не нужна)
2. Слева **Workers & Pages** → кнопка **Create**
3. Вкладка **Workers** → **Create Worker**
4. Имя: `diva-leads` → **Deploy**

Cloudflare покажет адрес вида `https://diva-leads.ваш-логин.workers.dev` —
он понадобится на шаге 4. Пока просто не закрывайте вкладку.

---

### Шаг 2. Вставить код

1. Нажать **Edit code**
2. Удалить всё, что там есть
3. Открыть файл `cloudflare-worker.js` из проекта, скопировать **целиком**
   и вставить
4. Нажать **Deploy** справа вверху

---

### Шаг 3. Положить туда токен

1. Вернуться в воркер → **Settings** → **Variables and Secrets**
2. Нажать **Add** три раза и завести:

   | Имя переменной | Тип | Значение |
   |---|---|---|
   | `TELEGRAM_BOT_TOKEN` | **Secret** | новый токен из шага 0 |
   | `TELEGRAM_CHAT_ID` | **Secret** | `-1002276800723` |
   | `ALLOWED_ORIGINS` | Text | `https://ваш-домен.com` |

3. **Deploy** ещё раз — без этого переменные не подхватятся

> Тип **Secret** важен: такое значение потом нельзя подсмотреть даже в
> панели Cloudflare.

---

### Шаг 4. Вписать адрес воркера в сайт

В файлах `apply.html` и `apply-form.html` найти строку `LEAD_ENDPOINT`
(она помечена стрелками) и заменить заглушку на адрес из шага 1:

```js
var LEAD_ENDPOINT = 'https://diva-leads.ваш-логин.workers.dev';
```

**В двух файлах.** Больше ничего менять не нужно.

---

### Шаг 5. Собрать архив и залить

```
sh make-archive.sh
```

Получится `diva-models-site.zip` — заливайте его на хостинг.

---

### Шаг 6. Проверить

Откройте сайт, заполните форму, отправьте.

| Что видно | Что это значит |
|---|---|
| «Заявка отправлена!» | всё работает, заявка уже в группе |
| Красная строка «Не удалось отправить» | см. таблицу ошибок ниже |

Экран успеха **никогда** не показывается, если сообщение не ушло, — иначе
заявки терялись бы незаметно.

## Что заливать на хостинг

`sh make-archive.sh` кладёт в архив только нужное: `.html`, `assets/` и
используемые картинки.

Не нужны на статическом хостинге: `send.php`, `api/`, `cloudflare-worker.js`,
`telegram-config*.php`, `serve.mjs`, `screenshot.mjs`, `node_modules/`, `*.md`.
Воркер живёт в Cloudflare, а не на вашем хостинге.

## Защита

- **Токен не попадает в браузер.** Страница обращается только к своему
  адресу, а сервер уже сам ходит в Telegram.
- **Ловушка для ботов.** В форме есть скрытое поле: человек его не видит,
  спам-бот заполняет. Такие заявки отбрасываются молча.
- **Ограничение частоты.** Не больше 5 заявок с одного IP за 10 минут,
  дальше — 429. Работает без базы, поэтому это заслон от потока, а не
  строгая гарантия.
- **Проверка данных.** Пустые поля отклоняются, длинные обрезаются, HTML
  экранируется — в сообщение нельзя подставить разметку.

## Проверка

Отправьте тестовую заявку:

| Что видно | Что это значит |
|---|---|
| Экран «Заявка отправлена!» | всё работает, сообщение уже в группе |
| Красная строка «Не удалось отправить» | сервер не принял — см. ниже |

Успех **никогда** не показывается, если сообщение не ушло, — иначе лиды
терялись бы незаметно.

Частые причины ошибки:

- `not_configured` — не заданы переменные окружения (или забыли Redeploy)
- `chat not found` — бота удалили из группы, или id без минуса
- `403 Forbidden` — бота заблокировали или исключили из группы
- 404 на адрес — `LEAD_ENDPOINT` не совпадает с вариантом хостинга
- `too_many_requests` — сработало ограничение частоты, подождите 10 минут

Ошибки пишутся в лог: на Vercel — вкладка **Logs**, на PHP — `error_log`.

## Если токен утёк

В @BotFather: `/revoke` → выбрать бота → он выдаст новый токен. Старый
перестаёт работать сразу. После этого обновить переменную окружения
(или `telegram-config.php`) и сделать Redeploy.
