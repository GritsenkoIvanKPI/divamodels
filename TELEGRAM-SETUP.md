# Заявки → Telegram

Заявки с сайта уходят в группу **DIVA MODELS** через бота **@bunxymodels_bot**.

Отправляют заявки два места, оба уже подключены:

| Форма | Файл | Метка в сообщении |
|---|---|---|
| Попап на сайте | `apply-form.html` | `Попап на сайте` |
| Рекламный лендинг | `apply.html` | `Рекламный лендинг` |

---

## Как это сейчас работает

Форма отправляет заявку **напрямую в Telegram, прямо из браузера**. Никакого
сервера не нужно — сайт можно залить куда угодно, хоть на GitHub Pages.

Токен вписан в двух файлах: `apply.html` и `apply-form.html`. Найти его
просто — ищите `TG_TOKEN`.

### ⚠️ Что нужно понимать про этот способ

Токен лежит в коде страницы, значит **его видно любому, кто откроет исходный
код сайта** (Ctrl+U). Это осознанный выбор ради простоты.

Что сможет сделать посторонний, если возьмёт токен:

- писать сообщения в вашу группу от имени бота (спам, обман от вашего лица);
- удалять сообщения, которые бот прислал, — то есть ваши заявки;
- читать то, что пишут **боту** напрямую (сами заявки он так не увидит:
  их бот отправляет, а не получает).

**Что делать, если начнётся спам:**

1. @BotFather → `/revoke` → выбрать бота → получить новый токен
2. вписать новый токен в `apply.html` и `apply-form.html` (строка `TG_TOKEN`)
3. перезалить эти два файла на хостинг

Старый токен перестаёт работать сразу.

### Если позже захотите закрыть токен

В проекте лежат три готовых варианта «посредника» — с ними токен в браузер
не попадает. Подключаются заменой одной строки в форме:

| Файл | Для чего |
|---|---|
| `cloudflare-worker.js` | статический хостинг (GitHub Pages) — бесплатно |
| `send.php` | обычный хостинг с PHP |
| `api/lead.js` | Node / Vercel / Netlify |

Инструкции — в комментариях внутри каждого файла.

## Что заливать на хостинг

`sh make-archive.sh` соберёт `diva-models-site.zip` — только то, что нужно
сайту: все `.html`, `assets/` и используемые картинки.

Не нужны на статическом хостинге: `send.php`, `api/`, `cloudflare-worker.js`,
`telegram-config*.php`, `serve.mjs`, `screenshot.mjs`, `node_modules/`, `*.md`.

## Защита

- **Токен не попадает в браузер.** Страница обращается только к своему
  адресу, а сервер уже сам ходит в Telegram.
- **Ловушка для ботов.** В форме есть скрытое поле: человек его не видит,
  спам-бот заполняет. Такие заявки отбрасываются молча.
- **Ограничение частоты.** Не больше 5 заявок с одного IP за 10 минут,
  дальше — 429. Работает без базы, поэтому это заслон от потока, а не
  строгая гарантия.
- **Проверка данных.** Пустые поля отклоняются, длинные обрезаются, HTML
  экранируется — в сообщение нельзя подставить разметку.

## Проверка

Отправьте тестовую заявку:

| Что видно | Что это значит |
|---|---|
| Экран «Заявка отправлена!» | всё работает, сообщение уже в группе |
| Красная строка «Не удалось отправить» | сервер не принял — см. ниже |

Успех **никогда** не показывается, если сообщение не ушло, — иначе лиды
терялись бы незаметно.

Частые причины ошибки:

- `not_configured` — не заданы переменные окружения (или забыли Redeploy)
- `chat not found` — бота удалили из группы, или id без минуса
- `403 Forbidden` — бота заблокировали или исключили из группы
- 404 на адрес — `LEAD_ENDPOINT` не совпадает с вариантом хостинга
- `too_many_requests` — сработало ограничение частоты, подождите 10 минут

Ошибки пишутся в лог: на Vercel — вкладка **Logs**, на PHP — `error_log`.

## Если токен утёк

В @BotFather: `/revoke` → выбрать бота → он выдаст новый токен. Старый
перестаёт работать сразу. После этого обновить переменную окружения
(или `telegram-config.php`) и сделать Redeploy.
